# Doggo 言語ガイド

このガイドは、変数、関数、条件分岐を学んだ人が、Doggo の基本を順に理解するための入門書です。

まだ環境を用意していない場合は、先に [15 分ではじめる Doggo](getting-started.md) を進めてください。このガイドの例は、作成したプロジェクトのルートで実行します。

最初の例を実行する前に、プロジェクトのルートで一度 `doggo build` を実行してください。以降の例は、構築した世代を `doggo exec --` で実行します。

各例では、値を画面に表示するために `(println 値)` を使います。関数呼び出しの規則は第 4 章で説明します。

## 1. S式とコードをデータとして扱う

### S式を使う理由

Doggo では、計算も関数定義も S式で書きます。S式はリストとして扱えるため、コード自体をデータとして扱い、新しいコードを組み立てられます。

### S式の読み方

丸かっこで囲んだ並びを S式と呼びます。通常は、最初の要素が処理で、残りの要素がその処理へ渡す値です。

たとえば `(+ 2 3)` は、`+` に `2` と `3` を渡します。

`(+ 2 3)` から結果の `5` を求めるように、式から値を求めることを評価と呼びます。先頭に `'` を付けると、式を評価せずデータとして扱います。この操作をクオートと呼びます。`'(+ 2 3)` は計算ではなく、`+`、`2`、`3` を並べたリストです。

### 例

次を `example.dog` に保存します。

```doggo
(println (+ 2 3))
(println '(+ 2 3))
```

プロジェクトのルートで実行します。

```console
$ doggo build
$ doggo exec -- example.dog
```

### 実行結果

```text
5
(+ 2 3)
```

1 行目は式を評価した結果です。2 行目は同じ形をデータとして表示した結果です。

### よくある間違い

データとしてのリストを書きたいのに `'` を付けないと、先頭要素を関数として呼び出そうとします。

反対に、計算したい式へ `'` を付けると、計算は行われません。

## 2. 数値、文字列、真偽値、nil、シンボル、キーワード

### 値の種類を区別する理由

`42` は数値、`"42"` は文字列、`:age` はキーワードです。値の種類によって利用できる処理や結果が異なるため、それぞれの表記と用途を理解する必要があります。

### 値の種類と書き方

整数は `42`、小数は `3.14` のように書きます。指数表記の `1.5e2` や `1.0e-4` も使えます。

文字列は二重引用符で囲みます。真偽値は `true` と `false` です。`nil` は値がないことを表します。

シンボルは、変数や関数を参照する名前です。`score` や `+` がシンボルです。シンボル自体を値にするときは `'score` のようにクオートします。

キーワードは `:score` のように先頭へ `:` を付けます。キーワードは自分自身として評価されるため、クオートは不要です。マップのキーによく使います。

### 例

次を `example.dog` に保存します。

```doggo
(println 42)
(println 1.5e2)
(println "こんにちは")
(println true)
(println false)
(println nil)
(println 'score)
(println :score)
```

プロジェクトのルートで実行します。

```console
$ doggo exec -- example.dog
```

### 実行結果

```text
42
150
"こんにちは"
true
false
nil
score
:score
```

### よくある間違い

文字列のつもりで `score` と書くと、Doggo は同名の変数を探します。文字そのものが必要なら `"score"`、名前を表すデータが必要なら `'score`、分類用の値が必要なら `:score` を使います。

`nil` と文字列の `"nil"` は別の値です。

## 3. リスト、ベクター、マップ、セット

### 用途と使い分け

複数の値を一つにまとめて扱う値を、コレクションと呼びます。Doggo のコレクションには、リスト、ベクター、マップ、セットがあります。これらを使うと、一覧、座標、設定、重複のない集合などを表せます。用途に合うコレクションを選ぶと、値をどのように扱うかがコードから分かります。

### コレクションの書き方と特徴

リストは丸かっこで表します。S式と同じ形のコードをデータとして扱う場合や、値を先頭から順に処理する場合に使います。ただし、丸かっこは通常は関数呼び出しになるため、データとしてのリストには `'` を付けます。

ベクターは角かっこで表します。順番を保ちたい一覧や、位置で取り出す値に使います。通常の一覧を表す場合は、まずベクターを選びます。

マップは波かっこでキーと値を交互に並べます。名前、点数、設定値のように、項目へ名前を付けて管理する場合に使います。`{:name "美香" :score 88}` では、`:name` と `:score` がキーです。キーワードを関数の位置に置くと、マップから対応する値を取得できます。

セットは `#{}` で表します。要素の順番を気にせず、重複を除いて値の有無を管理する場合に使います。`contains?` で値が含まれるか調べられます。

作成した値の内容を直接変更できない性質を不変と呼びます。これらのコレクションは不変であり、`conj` や `assoc` は元の値を変えず、新しい値を返します。詳しい操作は [標準ライブラリ](standard-library.md) で確認できます。

### 例

次を `example.dog` に保存します。

```doggo
(println '(1 2 3))
(println [1 2 3])
(println (:name {:name "美香" :score 88}))
(println (contains? #{:red :blue} :blue))
```

プロジェクトのルートで実行します。

```console
$ doggo exec -- example.dog
```

### 実行結果

```text
(1 2 3)
[1 2 3]
"美香"
true
```

### よくある間違い

マップの中は、キーと値を交互に書くため、要素数が偶数でなければなりません。`{:a 1 :b}` は `:b` に対応する値がなく、構文エラーです。キーの型は限定されず、`{1 :a}` も有効です。この場合は `1` がキー、`:a` が値になります。

`assoc` の戻り値を使わず、元のマップが変わると考えるのも間違いです。更新後の値には名前を付けるか、そのまま次の処理へ渡します。

## 4. 評価規則と関数呼び出し

### 評価規則を理解する理由

Doggo では、式の形によって評価のしかたが異なります。通常のリストは関数呼び出しとして評価され、クオートしたリストはデータとして扱われます。この違いを知ると、式がどの値になるかを追えるようになります。

### 式の評価規則

通常のリストでは、最初の要素を関数として評価します。続く引数も左から評価し、その結果を関数へ渡します。

`(+ 2 (* 3 4))` では、内側の `(* 3 4)` が `12` になります。その後、`+` に `2` と `12` が渡されます。

数値、文字列、真偽値、`nil`、キーワードは自分自身として評価されます。ベクター、マップ、セットでは、中に書いた式が評価されます。

シンボルは、対応する値を探して評価します。ローカルな名前を参照できる範囲は第 5 章、ファイルをまたいだ名前の管理は第 7 章で説明します。クオートされた式は、この通常の評価を行いません。

`if` や `let` のように、通常の関数とは異なる評価規則を持つ処理を特殊形式と呼びます。特殊形式は、引数をすべて先に評価するとは限りません。それぞれの規則は使う章で説明します。

### 例

次を `example.dog` に保存します。

```doggo
(println (+ 2 (* 3 4)))
```

プロジェクトのルートで実行します。

```console
$ doggo exec -- example.dog
```

### 実行結果

```text
14
```

### よくある間違い

一般的な数式のように `2 + 3` とは書きません。Doggo では演算子も関数の位置に置き、`(+ 2 3)` と書きます。

丸かっこの外へ引数を書くこともできません。呼び出し全体を一つのリストにします。

## 5. def、let、関数、スコープ

### 名前とスコープの役割

値や処理へ名前を付けると、あとからその名前で参照できます。名前を参照できる範囲をスコープと呼びます。広い範囲で共有する名前と、特定の処理だけで使う名前を分けることで、意図しない場所からの参照を防げます。

### 定義、束縛、関数の書き方

名前から値を参照できるようにする対応関係を、束縛と呼びます。Doggo では、`let` や関数の引数で作るローカル束縛と、`def` で現在の名前空間に作る定義を使い分けます。名前空間は、`def` で作った定義をまとめ、同じ名前の衝突を防ぐ単位です。

`def` は現在の名前空間へ名前を定義し、同じ名前空間の複数の関数から共有する値に使います。名前空間の宣言とファイル配置は第 7 章で説明します。

`let` は一時的なローカル束縛を作ります。束縛は角かっこの中へ名前と値を交互に書きます。`let` で束縛した名前は、後ろにある束縛と本体から参照できます。この範囲がローカルスコープです。

`fn` は関数を作ります。角かっこの中が引数で、引数の名前は関数の本体から参照できます。最後に評価した式が戻り値になります。

内側のスコープからは外側の名前を参照できますが、外側から内側の名前は参照できません。このように、コードの入れ子によって参照範囲が決まる規則をレキシカルスコープと呼びます。関数が定義された場所のローカル束縛を覚える性質は、クロージャと呼びます。

`defn` は、名前付き関数を定義するための簡潔な書き方です。最初は `def` と `fn` の組を理解してから使うと読みやすくなります。

### 例

次を `example.dog` に保存します。

```doggo
(def tax-rate 0.1)

(def total
  (fn [price]
    (let [tax (* price tax-rate)]
      (+ price tax))))

(def make-adder
  (fn [x]
    (fn [y] (+ x y))))

(def add10 (make-adder 10))

(println [(total 100) (add10 5)])
```

プロジェクトのルートで実行します。

```console
$ doggo exec -- example.dog
```

### 実行結果

```text
[110 15]
```

`add10` が呼ばれたときも、内側の関数は外側の引数 `x` の値 `10` を覚えています。

### よくある間違い

`let` の外からローカル名を参照することはできません。複数の場所で必要な値は戻り値にするか、関数の引数として渡します。

変更できる変数を前提に処理を書くのではなく、値を引数で受け取り、新しい値を返す関数を基本にします。

## 6. 条件分岐とループ

### 条件分岐と繰り返しの用途

入力に応じて処理を選び、同じ処理を必要な回数だけ繰り返すために使います。

### 分岐とループの書き方

`if` は条件、真の場合の式、偽の場合の式を受け取ります。Doggo では `false` と `nil` だけが偽です。`0` や空のコレクションは真として扱われます。

偽の場合の式を省略すると、条件が偽のときに `nil` を返します。複数の条件には `cond`、真のときだけ処理する場合には `when` も使えます。

処理が自分自身を呼び出して繰り返すことを再帰と呼びます。`loop` は、再帰で使うローカル束縛を作ります。`recur` は同じ `loop` へ新しい値を渡して戻ります。渡す値の数は、`loop` の束縛数と一致させます。

コレクションを順に処理するだけなら、後で扱う `map`、`filter`、`reduce` を先に検討します。

### 例

次を `example.dog` に保存します。

```doggo
(def describe-score
  (fn [score]
    (if (>= score 60) :pass :retry)))

(println (describe-score 75))

(println
  (loop [n 5 total 0]
    (if (> n 0)
      (recur (dec n) (+ total n))
      total)))
```

プロジェクトのルートで実行します。

```console
$ doggo exec -- example.dog
```

### 実行結果

```text
:pass
15
```

### よくある間違い

`if` は真の場合と偽の場合の片方だけを評価します。両方の処理が実行されるとは考えないでください。

`recur` は `loop` の中だけで使えます。通常の関数を再帰させる場合は、関数名を呼び出します。`recur` に渡す値の数が `loop` の束縛数と違う場合もエラーです。

`finally` を伴う `catch` の外側にある `loop` へ `recur` すると、コンパイルエラーになります。`catch` の内側に置いた `loop` での `recur` は使用できます。

## 7. 名前空間とファイル配置

### コードを分割する理由

プログラムが大きくなると、同じ名前を別の役割で使いたくなります。名前空間で定義を分けると、名前の衝突を避け、各ファイルの役割を一つに絞れます。

### 名前空間とファイルの対応

`ns` はファイルの名前空間を宣言します。通常はファイルの先頭に置きます。

生成したプロジェクトでは、Doggo がソースコードを探し始める `src` ディレクトリをソースルートと呼びます。名前空間の点は、ソースルートからのディレクトリ区切りに対応します。`study.math` は `src/study/math.dog` に置きます。

別の名前空間は `:require` で読み込みます。`:as math` を指定すると、`math/double` のように短い別名で参照できます。

[はじめかた](getting-started.md) で生成したプロジェクトには、`src`、`test`、`doggo.mod`、`doggo.lock` が用意されています。この配置をそのまま使うのが最短です。

### 例

次の二つのファイルを作成します。

`src/study/math.dog` に保存します。

```doggo
(ns study.math)

(def double
  (fn [x] (* x 2)))
```

`src/study/main.dog` に保存します。

```doggo
(ns study.main
  (:require [study.math :as math]))

(println (math/double 21))
```

プロジェクトのルートで実行します。

```console
$ doggo exec -- src/study/main.dog
```

### 実行結果

```text
42
```

### よくある間違い

名前空間とファイルパスが対応していないと、`:require` はファイルを見つけられません。`study.math` なら `study/math.dog` という対応を保ちます。

`double` のように名前だけで参照するものを無修飾名、`math/double` のように別名を付けて参照するものを修飾名と呼びます。読み込んだ名前には、まず `:as` と修飾名を使うと、定義元が分かりやすくなります。

## 8. 例外とエラー処理

### 例外が必要な場面

例外は、通常の処理を中断し、失敗を呼び出し元へ伝える値です。ファイルがない場合や入力が不正な場合は、通常の戻り値だけでは失敗理由を十分に伝えられません。例外へメッセージとデータを持たせると、呼び出し側が理由に応じて処理できます。

### 例外の作成、送出、捕捉

`ex-info` は、メッセージとデータのマップから例外値を作ります。3 番目の引数には原因となった例外を指定できます。

`throw` は例外を送出します。`try` の中で送出された例外は、`catch` で受け取れます。処理できない例外は再度 `throw` して呼び出し元へ渡します。

`ex-message` はメッセージを返します。`ex-data` は付加データを返します。`ex-cause` は原因を返し、原因がなければ `nil` です。

`ex->map` は例外を `:message`、`:data`、`:cause`、`:trace` を持つマップに変換します。記録や表示のために、例外全体をデータとして調べたいときに使います。

`finally` を付けると、正常終了でも例外でも最後に実行されます。開いたファイルなどを閉じる処理に向きます。

### 例

次を `example.dog` に保存します。

```doggo
(let [inner (ex-info "読み込み失敗" {:path "data.txt"})]
  (try
    (throw (ex-info "処理失敗" {:step :load} inner))
    (catch [e]
      (println [(ex-message e)
                (:step (ex-data e))
                (ex-message (ex-cause e))
                (:message (ex->map e))]))))
```

プロジェクトのルートで実行します。

```console
$ doggo exec -- example.dog
```

### 実行結果

```text
["処理失敗" :load "読み込み失敗" "処理失敗"]
```

### よくある間違い

すべての例外を捕まえて `nil` を返すと、失敗理由が消えます。処理できる種類だけを `ex-data` で判定し、処理できない例外は再送出します。

人が読む情報だけをメッセージへ詰め込まず、プログラムが判定する値は `ex-data` のマップへ入れます。

## 9. 遅延シーケンスと高階関数

### 遅延評価と高階関数の利点

コレクションの各要素へ同じ処理を行う場合、手書きのループより短く意図を表せます。必要な要素だけ計算すれば、大きな入力や終わりのない並びも扱えます。

### シーケンスと高階関数の使い方

シーケンスは、コレクションを先頭から順に見るための共通の表現です。

遅延シーケンスは、要素が必要になるまで計算を遅らせます。`range`、`map`、`filter` などは遅延シーケンスを返します。

`map` は各要素を関数で変換します。`filter` は条件を満たす要素だけを残します。`reduce` は要素を一つの値へまとめます。

関数を引数として受け取る関数を高階関数と呼びます。`map` に渡す `(fn [x] (* x 2))` がその例です。

終わりのないシーケンスには `take` で上限を付けます。`vec` は渡されたシーケンスの要素を計算し、結果をベクターに格納します。関数ごとの詳しい引数は [標準ライブラリ](standard-library.md) を参照してください。

### 例

次を `example.dog` に保存します。

```doggo
(def doubles
  (map (fn [x] (* x 2)) (range)))

(println (vec (take 5 doubles)))
(println (reduce + 0 [1 2 3 4]))
```

プロジェクトのルートで実行します。

```console
$ doggo exec -- example.dog
```

### 実行結果

```text
[0 2 4 6 8]
10
```

### よくある間違い

終わりのない `(range)` 全体を数えたり、ベクターへ変換したりすることはできません。先に `take` で必要な個数へ制限します。

画面への出力、ファイル操作、状態変更のように、戻り値以外へ影響を与える処理を副作用と呼びます。副作用のために `map` を使うと、遅延評価によって実行時期が分かりにくくなります。値の変換には `map`、要素ごとに副作用を実行する場合には `doseq` を使います。

## 10. マクロ

### マクロが必要な場面

マクロは、S 式から S 式への変換を Doggo のコードで記述する仕組みです。通常の関数は、引数がすべて評価された後に呼び出されます。

マクロには評価前の S 式がデータとして渡され、マクロが返した S 式で元の呼び出しが置き換えられます。置き換え後の式が評価されるため、マクロは引数を評価する条件、順序、回数を制御できます。評価器自体に新しい規則を追加するのではなく、`if` など既存の特殊形式を組み合わせて新しい構文を定義します。

### マクロ展開

`defmacro` でマクロを定義します。逆引用符の `` ` `` は、展開後のコードのひな形を作ります。`~` は、その位置へ引数のコードを差し込みます。複数の式を差し込む場合は `~@` を使います。

`when`、`cond`、`defn` もマクロです。既存のマクロで足りる場合は、新しいマクロを作る必要はありません。

### 例

次を `example.dog` に保存します。

```doggo
(defmacro twice [form]
  `(+ ~form ~form))

(println (twice 6))
```

プロジェクトのルートで実行します。

```console
$ doggo exec -- example.dog
```

### 実行結果

```text
12
```

`(twice 6)` は、加算を行う式へ展開されてから実行されます。

### よくある間違い

値を受け取って値を返すだけなら、マクロではなく関数を使います。関数のほうが呼び出しとテストが単純です。

例の `twice` は引数の式を 2 回評価します。副作用を持つ式を渡すと副作用も 2 回起きます。実用のマクロでは、引数を評価する回数を明確に設計します。

## 11. Atom、Ref、Agent、Channel

### 変化する状態の安全な管理

実行中に変化する値を状態と呼びます。複数の処理が同じ時間帯に進むことを並行処理と呼びます。並行処理で状態を共有するときは、時間とともに変わる値を安全に管理する必要があります。Doggo は用途ごとに異なる仕組みを用意しています。

### 状態管理と値の受け渡し

`Atom` は、一つの状態を同期的かつ原子的に更新します。同期的な更新では、更新の完了を待ってから次の処理へ進みます。原子的な更新では、ほかの処理から途中の状態は見えません。`atom` で作り、`swap!` で現在値へ関数を適用します。カウンターや現在の設定のように、ほかの状態とまとめて更新する必要がない一つの値に向きます。

`Ref` は、関連する複数の状態を一つのトランザクションでまとめて更新します。トランザクションでは、関連する複数の変更を一まとまりとして反映します。変更は `dosync` の中で `alter` または `ref-set` を使って行います。口座間の振替や在庫と合計額の更新のように、複数の値を同時に変えて整合性を保つ場合に向きます。

処理を受け取った順に待たせる列をキューと呼びます。`Agent` は、状態を更新する関数をキューへ追加し、順番に実行します。`send` で追加した処理は非同期に実行されるため、呼び出し元は完了を待たずに先へ進みます。完了を待つ場所では `await` を使います。集計や進捗の記録のように、呼び出し元を待たせず、更新を受け付けた順に処理したい場合に向きます。

`Channel` は、並行する処理の間で値を受け渡します。送信された値を受信まで一時的に保持する場所をバッファと呼びます。`chan` で作り、`>!` で送信し、`<!` で受信します。`chan 1` の数値はバッファに保持できる値の個数です。複数の処理を段階的につなぐ場合や、値を作る処理と受け取る処理を分ける場合に向きます。

`@value` は `deref` の短縮表記です。`Atom`、`Ref`、`Agent` の現在値を読み取れます。

### 例

次を `example.dog` に保存します。

```doggo
(def counter (atom 0))
(swap! counter inc)
(println @counter)

(def left (ref 10))
(def right (ref 20))
(dosync
  (let [old-left @left]
    (ref-set left @right)
    (ref-set right old-left)))
(println [@left @right])

(def queued (agent 0))
(send queued inc)
(await queued)
(println @queued)

(def messages (chan 1))
(>! messages "完了")
(println (<! messages))
(close! messages)
```

プロジェクトのルートで実行します。

```console
$ doggo exec -- example.dog
```

### 実行結果

```text
1
[20 10]
1
"完了"
```

### よくある間違い

単一のカウンターに `Ref`、複数の関連状態に別々の `Atom` を使うと、必要以上に複雑になります。一つの独立した状態には `Atom`、まとめて更新する複数状態には `Ref` を選びます。

`Channel` の送受信は待機することがあります。同じ処理内で受信前に送る例では、例のようにバッファを用意します。バッファを使わない場合は、送信側を別の並行処理で動かします。

## 12. プロトコル、レコード、マルチメソッド

### データに応じた処理の切り替え

データの種類ごとに同じ名前の操作を変えたい場合があります。また、種類だけでなく、データに含まれる値で処理を選びたい場合もあります。

### プロトコル、レコード、マルチメソッドの役割

値の種類を型と呼びます。プロトコルは、複数の型が共通して持てる操作の組を定義します。`defprotocol` で操作を宣言し、`extend-type` またはレコードの定義内で実装します。

レコードは、名前と決まった項目を持つマップのようなデータです。レコードが持つ項目をフィールドと呼びます。`defrecord Student [name]` は、宣言した順にフィールド値を受け取る `->Student` と、マップで値を受け取る `map->Student` を作ります。キーワードでフィールドを取得できます。

呼び出す処理を選ぶための値をディスパッチ値と呼びます。マルチメソッドは、引数から求めたディスパッチ値で処理を選びます。`defmulti` でディスパッチ関数を決め、`defmethod` で値ごとの処理を登録します。`:default` の処理も登録できます。

### 例

次を `example.dog` に保存します。

```doggo
(defprotocol Named
  (display-name [this]))

(defrecord Student [name]
  Named
  (display-name [this] (:name this)))

(def student (->Student "葵"))
(println (display-name student))

(defmulti label :kind)

(defmethod label :student [value]
  (str "受講者:" (:name value)))

(defmethod label :default [value]
  "不明")

(println (label {:kind :student :name "葵"}))
```

プロジェクトのルートで実行します。

```console
$ doggo exec -- example.dog
```

### 実行結果

```text
"葵"
"受講者:葵"
```

### よくある間違い

フィールドをまとめたいだけなら、まずマップを使います。名前付きのデータ型やプロトコル実装が必要になった時点でレコードを選びます。

分岐が一か所だけなら `if` や `cond` で十分です。複数の場所から同じディスパッチ規則へ処理を追加するときに、マルチメソッドが役立ちます。

## 13. 現在の制約と代替手段

スクリプトの実行には、`doggo.mod` と、その内容を `doggo mod sync` で反映した `doggo.lock` が必要です。[はじめかた](getting-started.md) で生成したプロジェクト内で例を実行してください。

分数を直接表す書き方はありません。`1/2` と続けて書かず、除算の `(/ 1 2)` を使います。

値が条件を満たすかを調べ、`true` または `false` を返す関数を述語と呼びます。Doggo では関数の引数に型をあらかじめ書かないため、外部入力は述語や検証用の関数で確認します。重要な処理にはテストを用意します。

終わりのない `(range)` に `count` を使うとエラーになります。`take` で有限個に制限してから処理します。

`ref-set` と `alter` は `dosync` の外では使えません。`Channel` の送受信は待機するため、バッファまたは別の並行処理を用意します。

Go の機能を呼び出す場合は、言語の基本とは別に [Go 連携](go-interop.md) の対応範囲と書き方を確認してください。Doggo がソースコードを読み、実行する流れを知りたい場合は、[Doggo の仕組み](how-doggo-works.md) へ進んでください。
